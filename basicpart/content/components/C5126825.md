## What it is

SPI NAND sits between the SPI NOR flash most microcontrollers boot from and the
eMMC used in Linux systems. It uses the same simple SPI wiring as NOR flash, but
NAND storage inside — which means far more capacity per dollar, at the cost of
needing the host to handle bad blocks and error correction. [1]

This part holds 512 megabits, which is 64 megabytes: sixteen times the W25Q128JV
NOR flash in this catalog, at a lower price. [1]

| Operating temperature | −40 °C to +85 °C [1] | Industrial range. |

## What the specification implies

**NAND needs error correction, and this part has it built in.** ECC is listed
among the features, which removes the hardest part of using raw NAND. Bad-block
management, however, is *not* listed — that remains the host's job, unlike on the
eMMC part.

**Erase and program timing are very different from NOR.** Block erase is 2 ms and
page program 350 µs, against the W25Q128JV's 120 ms for a 32 kB block erase. NAND
erases far faster, which is one of its real advantages for logging.

**Execute-in-place is not possible.** NOR flash can be read randomly, byte by
byte, which is why a microcontroller can run code directly from it. NAND must be
read a page at a time into a buffer. This part cannot replace the QSPI flash next
to an RP2040.

**1.8 V is the constraint that decides everything.** Most microcontrollers in
this catalog are 3.3 V parts. Using this flash means either a 1.8 V-capable
device or a level shifter on four SPI lines.

## Watch out for

- **Stock was zero at the snapshot date.** See `ISSUES.md`.
- **1.8 V only.** Not a drop-in for 3.3 V NOR flash.
- **Not execute-in-place.** Cannot be a microcontroller's program store.
- **You still handle bad blocks.** NAND ships with factory-marked bad blocks and
  develops more; your firmware or filesystem must cope.
